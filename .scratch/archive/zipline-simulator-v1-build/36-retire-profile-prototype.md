### Scope, measured before touching anything

The deletion is smaller than the reference count suggests. `rg` finds « prototype » in **15 files
outside the prototype**, but **every real import lives inside the prototype's own entry file**:

```
src/routes/prototype.profile-view.tsx:11-17
  → ./-prototype-07/{scenarios.ts, switcher.tsx, use-model.ts, variant-a…d.tsx}
```

Everything else is **prose** — doc comments and test descriptions recording where a number or an
algorithm came from — plus `contract.test.ts`'s directory filter. **Nothing in production imported
it**, so the deletion could not break a build path, and did not.

### The three residues the audit flagged, each ruled

1. **Prose re-worded to past tense — only where it became false.** Most references were *already*
   past tense and are legitimate provenance (« the prototype had it backwards », « how the
   prototype's ×5,02 happened ») — those are left alone, because deleting the artifact does not
   delete the history that explains a constant. Four were re-worded because they described the
   prototype as *present* or its deletion as *forthcoming*: `sweep.bench.ts` (« a route scheduled for
   deletion », « the deletion at P3 takes with it »), `bench-harness.ts` (a live path reference),
   `parameterise.test.ts` (« the prototype **implements** no inverse mode ») and `jacobian.test.ts`
   (« the prototype **exposes** no Jacobian »).
2. **`.oxfmtrc.json`'s prototype `ignorePatterns` entry removed**, together with the sentence in
   `AGENTS.md` / `CLAUDE.md` that explained it — which now reads « Markdown and
   `src/routeTree.gen.ts` … the route tree is generated ».
3. **`contract.test.ts`'s `startsWith("-prototype")` filter kept**, on the owner's call, and its
   docblock now says why: it costs one line, and without it a directory reintroduced under that name
   would be **silently unscanned by every § 5 prohibition below it** — the failure mode being guards
   that keep passing while the thing they guard walks back in.

### One claim this ticket carried that is **not** re-evidenced

The « ~33,6 KB/s of hydration dumps, OOM-killed a server at 209 s » leak is a **prior measurement,
left as such**. A dev server did die mid-session during this work (`ERR_CONNECTION_REFUSED`), but the
prototype route was never loaded and that server's log holds **165 bytes** and no dumps — so the
death is unrelated and cannot be offered as corroboration. The leak was a side benefit of the
deletion, never a gate for it, and the deletion stands on its acceptance items alone.
